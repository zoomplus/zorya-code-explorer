# Zorya Code Explorer

Локальный MCP-сервер для навигации по TypeScript- и JavaScript-коду. Он использует рабочие файлы выбранного проекта; для Git-проекта читает текущий worktree. Показывает диаграммы, связи и исходники с диапазонами строк и хешами.

## Установка

Попросите агента одной фразой:

> Установи MCP из https://github.com/zoomplus/zorya-code-explorer в текущий проект и проверь его.

Репозиторий и установщик общедоступны; аккаунт GitHub не нужен. Для загрузки сборки не нужно клонировать исходный код, настраивать GitHub CLI или вручную проверять checksum. Нужны Node.js 20.19 или новее и npm.

Установщик загружает закреплённый архив `v0.1.0`, сверяет его с версионной `SHA256SUMS`, проверяет содержимое и устанавливает его вне проекта. Он запускает `npm ci --omit=dev --ignore-scripts` и регистрирует MCP только в конфигурации целевого Codex-проекта. Глобальные настройки и файлы проекта не меняются.

### Если агенту нужны команды

Linux/macOS: запустите их из целевого проекта; кавычки сохраняют пробелы в путях.

```sh
set -eu
TARGET="$(pwd -P)"
BOOTSTRAP_DIR="$(mktemp -d)"
BOOTSTRAP="$BOOTSTRAP_DIR/install.mjs"
curl --fail --location --output "$BOOTSTRAP" https://raw.githubusercontent.com/zoomplus/zorya-code-explorer/installer-v1/install.mjs
node "$BOOTSTRAP" --project "$TARGET"
```

Windows PowerShell:

```powershell
$ErrorActionPreference = 'Stop'
$Target = (Get-Location).Path
$TempRoot = Join-Path $env:TEMP ('zce-' + [guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $TempRoot | Out-Null
$Bootstrap = Join-Path $TempRoot 'install.mjs'
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/zoomplus/zorya-code-explorer/installer-v1/install.mjs' -OutFile $Bootstrap
node $Bootstrap --project $Target
if ($LASTEXITCODE -ne 0) { throw 'Zorya Code Explorer installation failed' }
```

Передавайте `--project` точный путь к выбранному проекту. `.git` не обязателен, если Codex распознал обычную проектную конфигурацию `.codex/config.toml`. Установщик отказывается перезаписывать существующий checkout: для повторного использования он требует сверить его с чистой проверенной распаковкой архива; при расхождении оставьте имеющиеся файлы нетронутыми и остановитесь.

## Проверка подключения

Разрешение клиенту читать проектную MCP-конфигурацию и доверие к серверу подтверждает пользователь; не включайте автоматическое одобрение. После подтверждения откройте новый чат и проверьте через реальный MCP-клиент:

1. MCP handshake проходит и `tools/list` возвращает 14 инструментов.
2. `explorer_open` для целевого проекта возвращает `snapshot.root`, совпадающий с его точным абсолютным корнем.
3. `explorer_source` читает сущность из полученного кадра.

Не объявляйте установку завершённой, пока исходник не прочитан из точного проекта.

Инициализация и обнаружение tools могут выполняться одновременно. Если один процесс владеет локальной БД workspace, а второй анализирует ту же папку, второй может получить `workspace_busy`: заверши или закрой первую MCP-сессию и повтори; не удаляй lock вручную. Разные проекты изолированы.

По умолчанию доступно только чтение. Для записей и проверок владелец может передать отдельный JSON operator config вне проекта и указать его при запуске bootstrap через `--config <абсолютный-путь>`. Пример Linux для проекта с уже работающей командой `npm run typecheck`:

```json
{
  "stdio": {
    "principalId": "local",
    "grants": ["read", "write", "validate", "publish"]
  },
  "checkProfiles": [
    {
      "id": "typecheck",
      "executable": "/usr/bin/npm",
      "args": ["run", "typecheck"],
      "timeoutMs": 120000
    }
  ]
}
```

Замени `/usr/bin/npm` на абсолютный путь к исполняемому файлу в своей системе. Оставляй только необходимые grants и allowlisted команды; не сохраняй config в проекте. Внешние embeddings/reranking настраиваются отдельно и передают провайдеру запросы и фрагменты кода.

## Возможности и ограничения

- Обзор, навигация по кадрам, чтение исходников, ограниченный граф потока управления и отчёты о ссылках и тестах.
- Лексический локальный поиск включён по умолчанию; неизменённые фрагменты повторно используются при индексации.
- Embeddings и reranking выключены. При явном подключении внешнего провайдера ему передаются кодовые фрагменты и поисковые запросы.
- Структурный анализ предназначен для TypeScript и JavaScript. Статические связи не доказывают runtime-поведение; неподдерживаемые конструкции и пропуски покрытия остаются видимыми. При `source_changed` или устаревшем кадре обновите индекс и выберите цель заново.
- MCP-транспорт использует локальный `stdio`; облачного сервера и HTTP-шлюза нет.
- По умолчанию доступны операции чтения. Запись и проверки требуют отдельного operator config владельца вне проекта с конкретными правами и allowlisted командами.

## Распространение

Дистрибутив предназначен для использования приглашёнными владельцем получателями. Метаданные `UNLICENSED` сохранены: публичная доступность установщика и бинарного архива сама по себе не делает продукт открытым. TypeScript-исходники и их история в этом репозитории не публикуются. Собранный JavaScript можно копировать или изучать; упаковка не защищает от этого.

В [docs/reuse-prompt.md](docs/reuse-prompt.md) приведён общий запрос для адаптации других MCP-серверов к локальному использованию.
