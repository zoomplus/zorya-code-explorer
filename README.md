# Zorya Code Explorer

Локальный MCP-сервер для навигации по JavaScript- и TypeScript-проекту. Он читает текущие рабочие файлы выбранного проекта и показывает структуру, связи и исходники с диапазонами строк и хешами.

## Установка

Достаточно попросить агента:

> Установи MCP из https://github.com/zoomplus/zorya-code-explorer в текущий проект и проверь его.

Аккаунт GitHub и GitHub CLI не нужны. Нужны Node.js 20.19 или новее и npm. Bootstrap скачивает закреплённый бинарный архив и checksum, проверяет содержимое и ставит production-зависимости через `npm ci --omit=dev --ignore-scripts`. Архив и зависимости хранятся вне проекта; MCP записывается только в `<проект>/.codex/config.toml`, а инструкция добавляется в `.agents/skills/zorya-code-explorer/SKILL.md`. Установщик не меняет глобальные настройки, `package.json` или зависимости проекта и сохраняет посторонние параметры проектной конфигурации.

После установки сервер **настроен**, но это ещё не значит, что клиент перечитал конфигурацию или подключил инструменты. Разрешение клиенту использовать проектную конфигурацию и доверие к MCP остаются за пользователем; автоматическое одобрение не включается. Если tools отсутствуют в текущем клиенте, перечитайте конфигурацию или переподключите MCP; при необходимости откройте новый чат. Установка сама не может добавить tools в уже загруженный каталог клиента.

`installer-v4` устанавливает выпуск `v0.1.3`. При обновлении он распознаёт точный неизменённый project skill версии `0.1.2`; изменённые владельцем файлы сохраняются, а конфликт останавливает установку до записи MCP-конфигурации.

Проверка считается завершённой после реального MCP handshake, `tools/list` с 15 инструментами, `explorer_open` с `snapshot.root`, совпадающим с точным путём проекта, и успешного `explorer_source` для сущности из этого кадра. Настроенная запись или список tools сам по себе не подтверждает чтение исходников нужного проекта.

Установщик `installer-v4` настраивает выпуск сервера `v0.1.3`. Чтобы ограничить доступ только чтением, добавьте `--read-only` в просьбу или команду. Флаг ограничивает эффективные права чтением и при более широких grants во внешнем operator config. Повторная установка обновляет только распознанную запись сервера и сохраняет существующий config и grants; уже включённый режим `--read-only` не снимается без явного запроса.

### Команды, если агенту нужен ручной запуск

Linux/macOS — запуск из целевого проекта:

```sh
set -eu
TARGET="$(pwd -P)"
BOOTSTRAP_DIR="$(mktemp -d)"
BOOTSTRAP="$BOOTSTRAP_DIR/install.mjs"
curl --fail --location --output "$BOOTSTRAP" https://raw.githubusercontent.com/zoomplus/zorya-code-explorer/installer-v4/install.mjs
node "$BOOTSTRAP" --project "$TARGET"
```

Для режима только чтения передайте `--read-only` последней командой:

```sh
node "$BOOTSTRAP" --project "$TARGET" --read-only
```

Windows PowerShell:

```powershell
$ErrorActionPreference = 'Stop'
$Target = (Get-Location).Path
$TempRoot = Join-Path $env:TEMP ('zce-' + [guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $TempRoot | Out-Null
$Bootstrap = Join-Path $TempRoot 'install.mjs'
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/zoomplus/zorya-code-explorer/installer-v4/install.mjs' -OutFile $Bootstrap
node $Bootstrap --project $Target
if ($LASTEXITCODE -ne 0) { throw 'Zorya Code Explorer installation failed' }
```

Укажите точный путь к выбранному проекту. `.git` не обязателен, если Codex распознал проект по конфигурации `.codex/config.toml`. Установщик не перезаписывает неизвестный checkout: он использует только чистую проверенную распаковку и останавливается при несовпадении файлов.

### Operator config

По умолчанию локальный сервер получает grants `read`, `write`, `validate` и `publish`. Это доступные операции, а не поручение выполнить их: агент должен начинать изменение, проверку или публикацию только по явной просьбе пользователя и соблюдать штатные подтверждения операций. Для постоянного ограничения прав передайте `--config <абсолютный-путь-к-json>`; файл должен находиться вне проекта. При повторной установке без `--config` текущий внешний config сохраняется.

Например, config может определить безопасный набор grants и дополнительные команды проверки:

```json
{
  "stdio": {
    "principalId": "local",
    "grants": ["read", "write", "validate", "publish"]
  },
  "checkProfiles": [
    {
      "id": "typecheck",
      "executable": "/usr/bin/npm",
      "args": ["run", "typecheck"],
      "timeoutMs": 120000
    }
  ]
}
```

Замените `/usr/bin/npm` на абсолютный путь своей системы. Оставляйте только нужные grants и allowlisted команды. Не сохраняйте config в проекте и не отправляйте секреты в чат. С `--read-only` эффективными остаются только grants чтения, даже если config разрешает больше.

## Работа с кодом

- Для первого обзора проекта или архитектуры используйте `explorer_open` в режиме `overview`. Он строит содержательную структурную карту фактических модулей и подтверждённых связей вызовов.
- Для целевого поиска области или символа используйте режим `search`; переходы по сущностям сохраняют фокус. При смене кадра после шага проверяйте, где оказался фокус.
- При подробном разборе учитывайте `abstractionDepth` и не перескакивайте уровень, выбранный пользователем.
- После навигации подтвердите вывод чтением `explorer_source` и нужных связей. Диаграмма и статический граф — evidence для объяснения, а не доказательство runtime-порядка, dynamic dispatch или поведения framework.
- Для широкой просьбы о назначении или архитектуре главной схемой служит `explorer_present`; `explorer_flow` подходит для ветвей конкретной функции, когда пользователь спрашивает именно о её ходе. Прочитайте исходники, определите роли и границы по фактической реализации, сохраните все подтверждённые связи между выбранными узлами и скопируйте возвращённую Mermaid-схему точно. Не заменяйте её списком файлов.
- `explorer_present` объясняет роли узлов и смысл связей; проверяйте их по коду, не выводите их только из имени. `external` указывает на реальную границу за пределами проекта или процесса, а локальная заглушка остаётся локальным процессом.
- Если полезно сгруппировать выбранные сущности, передайте в `explorer_present` необязательные `groups: [{id, title, aliases, parentId?}]`. Группа рисуется как прямоугольный контейнер, а не как новый узел. Задавайте уникальный стабильный `id`; `aliases` берите только из выбранных узлов кадра. Один узел может иметь только одну непосредственную группу; `parentId` должен указывать на существующую группу. Пустые группы, неизвестные узлы или родители и циклы недопустимы; пределы — 40 групп и 8 уровней вложенности. Читайте исходники до группировки и различайте подтверждённые факты и интерпретацию агента. Группы не сливают дочерние обработчики, не меняют их aliases и реальные отношения; внутренняя фабрика их создания остаётся деталью реализации и не заменяет реальные узлы кадра. Дочерние aliases остаются доступны через `explorer_source`, `explorer_impact` и `navigator_step`; копируйте Mermaid целиком, включая `subgraph` и `end`. Если нужно сохранить текущую презентацию, не меняйте фокус или view ради групп.
- Алиас относится к той же сущности в пределах одного ID диалога и worktree. Он не является универсальным ID для другого диалога или checkout. Search ID символа включает snapshot и может измениться после правки исходника.
- Если карта выглядит перегруженной, используйте последний показанный кадр и ID сущностей, прочитайте их исходники и реальные вызовы. Определите, есть ли ошибка карты, полезное уточнение архитектуры или оба случая, прежде чем предлагать изменение; не сводите замечание автоматически к оформлению.

В проекте могут быть включены внешние embedding- или reranking-профили. Без них поиск использует локальный lexical режим. Настройка профиля означает только наличие конфигурации и не подтверждает, что провайдер доступен. Команда `status` показывает безопасную сводку без значений переменных окружения, но может построить индекс и обратиться к настроенному провайдеру; не запускайте её без нужды. `configured_not_verified` означает, что профиль настроен, а не что соединение проверено. Не запрашивайте и не передавайте credential в чате и не подменяйте выбранного провайдера другой моделью.

Встроенная проверка по умолчанию проверяет синтаксис поддерживаемых файлов JavaScript/TypeScript, включая JSX/TSX и декларации. Она не выполняет typecheck, тесты или scripts проекта. Для дополнительных команд владелец должен отдельно задать check profile в operator config.

## Распространение

Дистрибутив предназначен для приглашённых владельцем получателей. Метаданные `UNLICENSED` сохранены. Публичный installer и бинарный архив не означают открытую лицензию; TypeScript-исходники и Git-история в этом репозитории не публикуются. Собранный JavaScript можно копировать или изучать; упаковка не защищает от этого.

Общий запрос для адаптации других MCP-серверов к локальному использованию находится в [docs/reuse-prompt.md](docs/reuse-prompt.md).
