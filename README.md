# Zorya Code Explorer

Локальный MCP-сервер для навигации по JavaScript- и TypeScript-проекту. Он читает текущие рабочие файлы выбранного проекта и показывает структуру, связи и исходники с диапазонами строк и хешами.

## Установка

Достаточно попросить агента:

> Установи MCP из https://github.com/zoomplus/zorya-code-explorer в текущий проект и проверь его.

Аккаунт GitHub и GitHub CLI не нужны. Нужны Node.js 20.19 или новее и npm. Bootstrap скачивает закреплённый бинарный архив и checksum, проверяет содержимое и ставит production-зависимости через `npm ci --omit=dev --ignore-scripts`. Архив и зависимости хранятся вне проекта; MCP записывается только в `<проект>/.codex/config.toml`, а инструкция добавляется в `.agents/skills/zorya-code-explorer/SKILL.md`. Установщик не меняет глобальные настройки, `package.json` или зависимости проекта и сохраняет посторонние параметры проектной конфигурации.

После установки сервер **настроен**, но это ещё не значит, что клиент перечитал конфигурацию или подключил инструменты. Разрешение клиенту использовать проектную конфигурацию и доверие к MCP остаются за пользователем; автоматическое одобрение не включается. Если tools отсутствуют в текущем клиенте, перечитайте конфигурацию или переподключите MCP; при необходимости откройте новый чат. Установка сама не может добавить tools в уже загруженный каталог клиента.

`installer-v6` устанавливает выпуск `v0.1.5` из архива `zorya-code-explorer-v0.1.5.tgz` (72 811 байт, SHA-256 `52272c40a4af16a1dbb91d7cefd9c4c5680204cd810afc9b28c9b7739dab7ea5`). При обновлении он распознаёт известные неизменённые project skills предыдущих выпусков; изменённые владельцем файлы сохраняются, а конфликт останавливает установку до записи MCP-конфигурации.

Проверка считается завершённой после реального MCP handshake и `tools/list`, `explorer_open` с `snapshot.root`, совпадающим с точным путём проекта, и успешного `explorer_source` для сущности из этого кадра. Настроенная запись или список tools сам по себе не подтверждает чтение исходников нужного проекта.

Установщик `installer-v6` настраивает выпуск сервера `v0.1.5`. По умолчанию сервер разрешает чтение и изменение файлов; `--read-only` или `stdio.readOnly: true` ограничивает его чтением. Старое поле `stdio.grants` принимается только для миграции: точный полный набор `read`, `write`, `validate`, `publish` сохраняет редактирование, любой ограниченный набор включает режим только чтения. Установщик не переписывает внешний config; замените старое поле на `stdio.readOnly`. Одновременное использование `stdio.grants` и `stdio.readOnly` отклоняется. При повторной установке без `--config` текущий внешний config сохраняется.

### Команды, если агенту нужен ручной запуск

Linux/macOS — запуск из целевого проекта:

```sh
set -eu
TARGET="$(pwd -P)"
BOOTSTRAP_DIR="$(mktemp -d)"
BOOTSTRAP="$BOOTSTRAP_DIR/install.mjs"
curl --fail --location --output "$BOOTSTRAP" https://raw.githubusercontent.com/zoomplus/zorya-code-explorer/installer-v6/install.mjs
node "$BOOTSTRAP" --project "$TARGET"
```

Для режима только чтения передайте `--read-only` последней командой:

```sh
node "$BOOTSTRAP" --project "$TARGET" --read-only
```

Windows PowerShell:

```powershell
$ErrorActionPreference = 'Stop'
$Target = (Get-Location).Path
$TempRoot = Join-Path $env:TEMP ('zce-' + [guid]::NewGuid().ToString())
New-Item -ItemType Directory -Path $TempRoot | Out-Null
$Bootstrap = Join-Path $TempRoot 'install.mjs'
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/zoomplus/zorya-code-explorer/installer-v6/install.mjs' -OutFile $Bootstrap
node $Bootstrap --project $Target
if ($LASTEXITCODE -ne 0) { throw 'Zorya Code Explorer installation failed' }
```

Укажите точный путь к выбранному проекту. `.git` не обязателен, если Codex распознал проект по конфигурации `.codex/config.toml`. Установщик не перезаписывает неизвестный checkout: он использует только чистую проверенную распаковку и останавливается при несовпадении файлов.

### Operator config

По умолчанию сервер разрешает чтение и изменение файлов; это не поручение выполнять незапрошенную работу. Для ограничения записи передайте `--read-only` при запуске или задайте `"stdio": { "readOnly": true }` во внешнем operator config. Поле `stdio.grants` оставлено только для обратной совместимости: ровно полный набор прежних grants сохраняет редактирование, любой сокращённый набор становится режимом только чтения. Замените legacy поле на `stdio.readOnly`; не объединяйте оба поля. Внешний config передают через `--config <абсолютный-путь-к-json>` и хранят вне проекта. Повторная установка без `--config` сохраняет текущий внешний config.

Например, внешний config может включить режим только чтения и дополнительные команды проверки:

```json
{
  "stdio": {
    "principalId": "local",
    "readOnly": true
  },
  "checkProfiles": [
    {
      "id": "typecheck",
      "executable": "/usr/bin/npm",
      "args": ["run", "typecheck"],
      "timeoutMs": 120000
    }
  ]
}
```

Замените `/usr/bin/npm` на абсолютный путь своей системы. Оставляйте только нужные allowlisted команды. Не сохраняйте config в проекте и не отправляйте секреты в чат. Флаг `--read-only` нельзя снять через config; без флага значение `stdio.readOnly` задаёт постоянное ограничение.

## Работа с кодом

- Для первого обзора проекта или архитектуры используйте `explorer_open` в режиме `overview`. Он строит содержательную структурную карту фактических модулей и подтверждённых связей вызовов.
- Для целевого поиска области или символа используйте режим `search`; переходы по сущностям сохраняют фокус. При смене кадра после шага проверяйте, где оказался фокус.
- Для локального увеличения контекста используйте `explorer_zoom`: выбранные anchors сохраняются вместе с исходными заголовками и типами, родительские группы остаются на месте, а соседи добавляются из реальных связей индексированного проекта.
- При подробном разборе учитывайте `abstractionDepth` и не перескакивайте уровень, выбранный пользователем.
- После навигации подтвердите вывод чтением `explorer_source` и нужных связей. Диаграмма и статический граф — evidence для объяснения, а не доказательство runtime-порядка, dynamic dispatch или поведения framework.
- Для широкой просьбы о назначении или архитектуре главной схемой служит `explorer_present`; `explorer_flow` подходит для ветвей конкретной функции, когда пользователь спрашивает именно о её ходе. Прочитайте исходники, укажите у каждого узла тип исходной сущности, человеческое назначение и alias, сохраните все подтверждённые связи между выбранными узлами и скопируйте возвращённую Mermaid-схему со встроенной легендой целиком. Не заменяйте её списком файлов.
- В архитектурной карте видимый префикс `<тип> · <назначение> · <alias>` и геометрию задаёт исходный `kind`, а поле `role` сохраняется как метаданные ответственности для совместимости API. Формы: `Класс` — двойной прямоугольник `[[ ]]`; `Функция` и `Вызываемый элемент` — скруглённая форма `( )`; `Метод` — прямоугольник `[ ]`; `Конструктор` — трапеция `[/ \]`; `Интерфейс` и `Тип` — шестиугольник `{{ }}`; `Модуль` и `Проект` — асимметричная форма `> ]`. Известные дополнительные типы используют собственную русскую метку и форму. Неизвестный непустой `kind` показывается исходным значением в нейтральном прямоугольнике, без догадки; в легенде он подписывается `Неизвестный тип («<kind>») — прямоугольник`. Пустое значение подписывается `Неизвестный тип (пустое значение)`.
- `role` описывает ответственность узла, но не выбирает его геометрию. Продолжай выводить `external` только из подтверждённой границы за пределами проекта или процесса; имя сущности не является доказательством. Фактический вид целой функции или метода в архитектурной карте не кодирует её внутренние ветви.
- Встроенная легенда перечисляет только типы, встречающиеся в карте. Её подпись `Легенда типов · образцы, не сущности проекта` отделяет примеры форм от сущностей; примеры не получают aliases и остаются вне code-групп. Копируй Mermaid и легенду дословно, не меняй формы по `role` и не удаляй type prefix. `explorer_flow` сохраняет собственную грамматику потока управления: ромбы и начальные/конечные узлы относятся к подтверждённым решениям и завершениям, а истинная и ложная ветви остаются явно подписанными условиями.
- Если полезно сгруппировать выбранные сущности, передайте в `explorer_present` необязательные `groups: [{id, title, aliases, parentId?}]`. Группа рисуется как прямоугольный контейнер, а не как новый узел. Задавайте уникальный стабильный `id`; `aliases` берите только из выбранных узлов кадра. Один узел может иметь только одну непосредственную группу; `parentId` должен указывать на существующую группу. Пустые группы, неизвестные узлы или родители и циклы недопустимы; пределы — 40 групп и 8 уровней вложенности. Читайте исходники до группировки и различайте подтверждённые факты и интерпретацию агента. Группы не сливают дочерние обработчики, не меняют их aliases и реальные отношения; внутренняя фабрика их создания остаётся деталью реализации и не заменяет реальные узлы кадра. Дочерние aliases остаются доступны через `explorer_source`, `explorer_impact` и `navigator_step`; копируйте Mermaid целиком, включая `subgraph` и `end`. Если нужно сохранить текущую презентацию, не меняйте фокус или view ради групп.
- Алиас относится к той же сущности в пределах одного ID диалога и worktree. Он не является универсальным ID для другого диалога или checkout. Search ID символа включает snapshot и может измениться после правки исходника.
- Если карта выглядит перегруженной, используйте последний показанный кадр и ID сущностей, прочитайте их исходники и реальные вызовы. Определите, есть ли ошибка карты, полезное уточнение архитектуры или оба случая, прежде чем предлагать изменение; не сводите замечание автоматически к оформлению.

По умолчанию поиск использует локальный lexical режим. Если оператор настроит `searchProviders`, embeddings и rerank выполняются публичными адаптерами Zorya Search SDK; явные модели, пространства и пользовательские endpoints сохраняются. В config указывайте только имя переменной через `apiKeyEnv`; значение credential задаётся в окружении и не помещается в config, URL или архив. Настройка профиля сама по себе не подтверждает доступность провайдера. Команда `status` показывает безопасную сводку без значений переменных окружения, но может построить индекс и обратиться к настроенному провайдеру; не запускайте её без нужды. `configured_not_verified` означает, что профиль настроен, а не что соединение проверено. Не запрашивайте и не передавайте credential в чате и не подменяйте выбранного провайдера или модель.

Встроенная проверка по умолчанию проверяет синтаксис поддерживаемых файлов JavaScript/TypeScript, включая JSX/TSX и декларации. Она не выполняет typecheck, тесты или scripts проекта. Для дополнительных команд владелец должен отдельно задать check profile в operator config.

## Распространение

Дистрибутив предназначен для приглашённых владельцем получателей. Метаданные `UNLICENSED` сохранены. Публичный installer и бинарный архив не означают открытую лицензию; TypeScript-исходники и Git-история в этом репозитории не публикуются. Собранный JavaScript можно копировать или изучать; упаковка не защищает от этого.

Общий запрос для адаптации других MCP-серверов к локальному использованию находится в [docs/reuse-prompt.md](docs/reuse-prompt.md).
