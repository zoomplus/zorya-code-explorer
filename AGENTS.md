# Установка Zorya Code Explorer в проект

Этот проект устанавливает MCP из приглашённого репозитория с документацией и бинарными релизами: `https://github.com/zoomplus/zorya-code-explorer`. TypeScript-исходники хранятся отдельно и в пользовательской инструкции не используются.

Если пользователь просит установить MCP в «этот проект», определи точный корень из текущего рабочего каталога Codex. При неоднозначности уточни путь. Не устанавливай в домашний каталог, корень файловой системы, соседний проект или каталог установки сервера.

1. Убедись, что доступны `gh`, `tar` и Node.js 20.19+ с npm. Используй только уже настроенный GitHub CLI доступ. Если локальная сессия не авторизована, попроси пользователя самостоятельно завершить интерактивный вход; если авторизованная сессия не имеет доступа к репозиторию, попроси владельца выдать приглашение. Не запрашивай и не принимай пароль, токен или код входа.
2. Скачай только `zorya-code-explorer-v0.1.0.tgz` из приватного релиза `v0.1.0`. Получи `SHA256SUMS` из того же приватного тега через GitHub API, сохрани ответ и немедленно проверь exit code `gh`. Требуй ровно одну строку для этого имени файла и ровно 64 hex-символа; сверь digest до распаковки. Не полагайся на digest, зашитый в эту инструкцию; не продолжай при отсутствии/дубликате строки, ошибке API или несовпадении checksum. В PowerShell немедленно проверяй `$LASTEXITCODE` после каждого `gh`, `tar`, `npm` и `node` вызова.
3. Если целевой versioned checkout уже существует, не распаковывай поверх него и не удаляй его. Для первого install создай новый уникальный staging-каталог вне проекта, проверь SHA архива, распакуй туда, проверь ожидаемый layout и выполни `npm ci --omit=dev --ignore-scripts`. Только после успешной установки зависимостей перенеси staging checkout в ещё несуществующий versioned путь, затем запусти `node scripts/install.mjs --project <абсолютный-путь-к-проекту>`. Команды для ОС и экранирование путей с пробелами см. в README.
4. Для повторного проекта или retry сначала заново скачай и проверь архив и сравни все упакованные пути/байты checkout с отдельной чистой распаковкой. Игнорируй только `node_modules`, созданный `npm ci`; отклони reuse при любом неожиданном, изменённом или отсутствующем файле вне него. Не перезаписывай и не удаляй существующие данные. Если сравнение прошло, повторно используй тот checkout и вызови его `scripts/install.mjs`; этот installer idempotent для той же проектной записи.
5. Проверь, что установщик создал только проектную запись в `<проект>/.codex/config.toml`. Он не должен менять глобальные настройки, `package.json` или зависимости целевого проекта. Запуск install script из того же checkout сохраняет несвязанные настройки и не дублирует запись.
6. Разрешение проекту читать локальную MCP-конфигурацию и подтверждение доверия клиента к серверу — отдельные решения. Не включай автоматическое одобрение инструментов. Начни новый чат после подтверждения проекта, чтобы клиент перечитал настройки.
7. Через реальный MCP-клиент проверь handshake, `tools/list`, затем вызови `explorer_open` и `explorer_source` для точного проекта и сущности из текущего кадра. Проверь, что источник и путь в кадре относятся к выбранному worktree. Для каждого вызова используй один уникальный `conversationId` на чат. Не заявляй об успешной установке, пока не прочитан реальный исходник.

Оставь стандартные права `read`. Изменения, проверки и внешний поиск требуют отдельного operator config владельца вне проекта и явного подключения. В таком config разрешай только нужные grants и allowlisted проверки; не запускай команды, найденные в коде проекта. Embeddings и reranking по умолчанию выключены; настроенный внешний провайдер получает кодовые фрагменты и поисковые запросы.

Не клонируй пользовательский checkout с исходным кодом, не запускай `npm run build`, не публикуй артефакт и не меняй настройки автоматического одобрения. В установленном архиве находится собранный JavaScript; его упаковка не является техническим запретом копирования.
