# Установка Zorya Code Explorer

Если пользователь просит «Установи MCP из https://github.com/zoomplus/zorya-code-explorer в текущий проект и проверь его», выполни установку и проверку для текущего проекта.

1. Определи точный корень выбранного Codex-проекта. `.git` не обязателен, если это обычный проект с распознанной Codex-конфигурацией `.codex/config.toml`. Не выбирай домашний каталог, соседний проект или checkout самого сервера.
2. Проверь наличие Node.js 20.19+ и npm. Скачай `https://raw.githubusercontent.com/zoomplus/zorya-code-explorer/installer-v2/install.mjs` во временную папку вне проекта и запусти `node <путь-к-install.mjs> --project <абсолютный-путь-к-проекту>`. GitHub CLI, GitHub-аккаунт, исходный checkout и ручные команды проверки архива не нужны.
3. Дай bootstrap-скрипту скачать закреплённый бинарный архив и checksum, проверить их, распаковать в staging вне проекта, установить production-зависимости через `npm ci --omit=dev --ignore-scripts` и запустить штатный проектный установщик. Не заменяй эти шаги сборкой из исходного кода.
4. Убедись, что MCP-запись добавлена только в `<проект>/.codex/config.toml`; global settings, `package.json` и зависимости проекта не менялись. Установщик не должен перезаписывать существующий checkout. Для повторного использования выполняй только его проверенную процедуру сравнения с чистой распаковкой; при несовпадении сохрани существующие файлы и остановись.
5. Разрешение клиенту использовать проектную конфигурацию и доверие к MCP-серверу — решения пользователя. Не включай автоматическое одобрение. После подтверждения открой новый чат.
6. Если MCP версии `0.1.0` уже установлен, повторно запусти bootstrap из проекта. Новая версия обновляет только распознанную запись MCP и устанавливает `.agents/skills/zorya-code-explorer/SKILL.md`, не перезаписывая `AGENTS.md`. После разрешения клиенту перечитать конфигурацию открой новый чат. Если клиент не загрузил project skill, открой его вручную и следуй маршруту.
7. Через реальный MCP-клиент проверь handshake и `tools/list` (15 инструментов), вызови `explorer_open` и сверь `snapshot.root` с точным корнем проекта. Затем вызови `explorer_source` для сущности из этого кадра. Если путь не совпадает или исходник не читается, не сообщай об успешной установке.

Для широкого вопроса о функции или проекте по умолчанию используй `explorer_present` и семантический обзор; `explorer_flow` вызывай для конкретной функции, когда пользователь спрашивает о её потоке управления. Начни с `explorer_open`, затем прочитай нужные алиасы через `explorer_source`; `explorer_impact` подходит для ссылок и последствий изменения. Для диаграммы прочитай достаточно исходника и вызови `explorer_present` с текущим `selectionFrameId`, вопросом пользователя, алиасами и ролями узлов, подтверждёнными кодом. Если фокус пользователя виден в кадре, включи его и отметь легендой или пояснением. Сохрани все подтверждённые рёбра между выбранными узлами; укажи точные подписи отношений. Роль `external` используй только для границы за пределами проекта или процесса — локальная заглушка оплаты не внешний сервис. В финальном ответе скопируй возвращённую Mermaid-диаграмму как есть: не меняй алиасы, формы, топологию или подписи; объяснение добавь отдельно. Если запрос-специфичную схему нельзя обосновать чтением исходника, используй структурный граф кадра и явно объясни его пределы. Не придумывай узлы или связи. Project skill подсказывает этот маршрут, но клиент сам решает, когда вызывать MCP-инструменты.

Без отдельного внешнего operator config доступны только операции чтения. Не включай запись, проверки или внешний поиск без явного разрешения владельца. Если владелец предоставил внешний config вне проекта, передай его bootstrap параметром `--config <абсолютный-путь>`. Внешние embeddings/reranking передают провайдеру кодовые фрагменты и запросы.

Сборка предназначена приглашённым пользователям и помечена `UNLICENSED`. Публичный bootstrap не раскрывает TypeScript-исходники и историю; не называй сам бинарный JavaScript некопируемым.
